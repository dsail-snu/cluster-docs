# 클러스터 사용 규정

!!! warning "모든 사용자가 반드시 숙지해야 합니다"
    규정을 몰라서 생긴 불이익은 도와드리기 어렵습니다.
    한 사람의 부주의가 다른 동료들의 연구 일정에 큰 지장을 줄 수 있습니다. 함께 쓰는 환경임을 배려해 주세요.

이 페이지는 공지된 사용 규정을 읽기 쉽게 정리한 것입니다. 관리자 공지와 다르면 공지가 우선합니다.

## 핵심 요약

1. **GPU를 점유하는 디버깅 잡**(인터랙티브 셸, 노트북, 대기 중인 추론 서버 등)은 **팀 QoS** + 잡 이름 **`debug`** 로 제출하고, 다 쓰면 **즉시 반납**하세요.
2. **SSH 키를 반드시 등록**하세요. 비밀번호를 여러 번 틀리면 접속 IP가 차단됩니다.
3. **AI 도구에게 SSH, 데이터 전송 같은 네트워크 작업이나 잡 제출을 시키지 마세요. 전면 금지입니다.**

## 잡 제출 규칙

- **팀 QoS는 본인 소속 팀 것**을 사용하세요. 본인 것이 무엇인지는 `qos` 로 확인합니다.
- **GPU를 요청할 때는 GPU 타입을 명시**하세요: `--gres=gpu:<GPU 타입>:4` 처럼. 타입 이름은 `sq` 또는 `sinfo -o "%G"` 로 확인합니다.
- **GPU 잡은 파티션, CPU 수, 메모리를 직접 설정하지 마세요.** GPU 수에 비례해 충분한 양이 **자동 할당**됩니다. 그보다 많이 잡으면 그 노드의 남은 GPU를 다른 사람이 쓰지 못합니다. 시스템이 강제합니다.

    파티션과 CPU 지정은 무시되고, 메모리를 적으면 제출이 거부됩니다. 처리 규칙 전체는
    [Slurm 레퍼런스: 자동 할당과 라우팅](../reference/slurm.md#자동-할당과-라우팅)에 있습니다.

- **CPU 전용 잡은 CPU 수를 필요한 만큼 자유롭게 지정**해도 됩니다. 파티션은 적지 마세요.
- **`--qos` 를 생략하면 기본 QoS로 제출됩니다.** 기본 QoS는 남는 자원을 쓰는 대신 **팀 QoS 잡에 선점될 수 있습니다**. 선점되면 잡이 큐로 돌아가 **처음부터** 다시 돕니다. 긴 잡은 반드시 체크포인트를 남기세요. -> [선점 설명](../reference/slurm.md#선점)

!!! tip "QoS가 무엇인지, 내 팀 QoS가 무엇인지 모르겠다면"
    `qos` 를 실행하세요. 쓸 수 있는 QoS, 선점 관계(무엇을 선점하고 무엇에 선점당하는지), 팀 몫 사용량이 한 번에 나옵니다.
    배경 설명은 [Slurm 레퍼런스: QoS](../reference/slurm.md#qos)를 보세요.

## 디버깅

디버깅을 위해 **GPU를 점유**해야 하는 경우가 있습니다.

!!! info "GPU를 점유한다는 것"
    인터랙티브 터미널, Jupyter Notebook, **요청을 기다리는 추론 서버** 등 **사용자가 GPU 사용 시점을 임의로 제어할 수 있는 모든 상황**을 말합니다.
    단, **데이터 처리가 끝나면 스스로 자원을 반납하도록 만든 자동화 잡**은 해당하지 않습니다.

### 디버깅용 GPU 점유 잡의 필수 규칙

| # | 규칙 | 예시 |
|---|---|---|
| 1 | **본인 소속 팀 QoS**로 제출 | `--qos=<팀 QoS>` (`qos` 로 확인) |
| 2 | **잡 이름을 `debug`** 로 | `--job-name=debug` |
| 3 | 다 쓰면 **즉시 반납** | 셸에서 `exit`, 또는 `scancel <JOBID>` |

```bash
# 디버깅용 인터랙티브 GPU 셸 (팀 QoS는 본인 것으로. `qos` 로 확인)
srun --qos=<팀 QoS> --job-name=debug --time=04:00:00 \
     --gres=gpu:<GPU 타입>:1 --pty bash -i
```

!!! note "인터랙티브 잡은 requeue되지 않습니다"
    `srun --pty`, `salloc` 잡은 선점되면 되살아나지 않고 그대로 사라집니다. 잃으면 곤란한 작업은 배치 잡으로 돌리세요.

!!! danger "위반 시"
    규칙을 지키지 않은 GPU 점유 잡은 **관리자 판단으로 강제 종료**될 수 있고, 누적되면 **제재 대상**이 됩니다.
    **연달아 오래 점유해 자원 순환을 막는다고 판단되는 경우**에도 같은 조치가 적용됩니다.

### 실행 중인 잡의 노드에 들어가야 할 때

작업 현황 확인이나 디버깅을 위해 잡이 도는 노드에 들어가야 한다면, 아래 명령으로 그 잡 안에 터미널을 받으세요.

```bash
srun --jobid=<JOBID> --overlap --pty bash -i
```

이 밖에 **시스템 감시를 우회**해 자원을 점유하거나, **할당받지 않은 자원을 비정상적으로 사용**하는 행위는 **무관용 원칙**으로 엄중히 조치합니다.

## 접속 보안

보안을 위해 **모든 노드의 방화벽이 켜져 있고**, 외부에서 접속하는 로그인 노드에는 **무차별 대입 방어**가 상시 동작합니다.

- 일정 기간 안에 **비밀번호를 여러 번 틀리면 접속 IP가 차단**됩니다. 차단 기준은 공개하지 않습니다.
- 차단 해제는 **관리자에게 요청**하세요. -> [도움 요청](../help.md)
- **반드시 SSH 키를 등록**해 비밀번호 없이 접속하세요. -> [SSH 키 등록 방법](../start/connect.md)
- 접속 주소와 포트는 계정을 발급할 때 관리자가 알려 줍니다 (`<로그인 주소>`, `<SSH 포트>`).

## 로그인 노드

로그인 노드는 모두가 함께 쓰는 접속 지점입니다. 안정성을 위해 **사용자별 자원 한도**(동시 사용 코어, 메모리, 프로세스와 스레드 수)가 걸려 있습니다. 정확한 값은 로그인 배너에 표시됩니다.

- VSCode 접속, 코드 편집, 가벼운 작업에는 지장이 없는 수준입니다.
- **무거운 연산은 반드시 Slurm으로 계산 노드에 제출**하세요. -> [첫 잡 실행하기](../start/first-job.md)
- 원격 편집은 **VSCode Remote-SSH**를 쓰세요. VSCode Tunnel은 로그인 노드의 CPU를 많이 차지합니다.

## AI 사용 규정

!!! danger "필독"
    AI 도구로 데이터 이전을 하다가 **SSH 접속을 끝없이 재시도하는 오류**가 생겨, 기관 네트워크에서 **클러스터 전체의 IP가 차단되는** 심각한 사고가 실제로 있었습니다.
    또한 AI를 통한 무분별한 잡 제출은 **GPU 자원 파편화**를 일으켜 전체 효율을 크게 떨어뜨립니다.

이를 막기 위해 다음을 **엄격히 금지**합니다.

- **AI 도구(코딩 에이전트, 챗봇 등)에게 SSH 접속, 데이터 전송 등 모든 네트워크 작업을 시키는 것.**
  네트워크 작업은 **반드시 사용자 본인이 직접 제어하고 수행**해야 합니다.
- **Slurm 잡 제출(`sbatch`, `srun`, `salloc`)을 AI에게 맡기는 것.**
  잡 제출도 **반드시 사용자가 직접** 해야 합니다.

| 괜찮은 것 | 안 되는 것 |
|---|---|
| AI로 코드를 작성하거나 리뷰하기 | AI 에이전트가 직접 `ssh`, `scp`, `rsync` 로 클러스터에 접속하거나 데이터를 옮기기 |
| AI로 문서나 자료 정리하기 | AI 에이전트가 직접 `sbatch`, `srun` 으로 잡을 제출하기 |
| AI가 만든 명령을 **사용자가 읽고 직접** 실행하기 | AI가 명령을 반복 실행하도록 맡겨 두기 |

규정을 지키지 않으면 부득이하게 **클러스터 이용이 제한**될 수 있습니다.

## 위반 시 조치

| 행위 | 결과 |
|---|---|
| 규칙을 지키지 않은 GPU 점유 잡 | 관리자 판단으로 강제 종료, 누적 시 제재 |
| 오래 연달아 점유해 자원 순환 방해 | 위와 같음 |
| 시스템 감시 우회, 비정상 자원 점유 | 무관용 원칙, 엄중 조치 |
| 비밀번호 반복 오류 | 접속 IP 차단 (관리자에게 해제 요청) |
| AI에게 네트워크 작업이나 잡 제출을 맡김 | 클러스터 이용 제한 가능 |

## 제출 전 체크리스트

- [ ] GPU 타입을 명시했나요? (`--gres=gpu:<GPU 타입>:N`)
- [ ] 디버깅용 GPU 점유라면 팀 QoS + 이름 `debug` 인가요? (`qos` 로 본인 QoS 확인)
- [ ] 기본 QoS로 도는 긴 잡이라면 선점에 대비해 체크포인트를 남기나요?
- [ ] GPU 잡이라면 파티션, CPU, 메모리를 직접 지정하지 않았나요? (메모리를 적으면 제출이 거부됩니다)
- [ ] 잡 제출을 **내가 직접** 하나요? (AI에게 맡기지 않기)

실제 명령 예시는 [잡 레시피](../guide/job-recipes.md)를 보세요.
