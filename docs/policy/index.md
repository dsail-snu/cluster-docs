# 클러스터 사용 규정

!!! warning "모든 사용자가 반드시 숙지해야 합니다"
    규정을 몰라서 생긴 불이익은 도와드리기 어렵습니다.
    한 사람의 부주의가 다른 동료들의 연구 일정에 큰 지장을 줄 수 있습니다. 함께 쓰는 환경임을 배려해 주세요.

이 페이지는 공지된 사용 규정을 읽기 쉽게 정리한 것입니다. 공지와 다르면 공지가 우선합니다.

## 핵심 요약

1. **GPU를 점유하는 세션**(인터랙티브 셸, 노트북, 대기 중인 추론 서버 등)은 **팀 QoS**로 실행하고, 다 쓰면 **즉시 반납**하세요.
2. **SSH 키를 반드시 등록**하세요. 비밀번호를 여러 번 틀리면 접속 IP가 차단됩니다.
3. **AI 에이전트(Claude Code, Codex CLI 등)는 쓸 수 있지만, [AI 에이전트 규칙](ai-agents.md)을 반드시 따라야 합니다.** 사용하는 에이전트에 규칙을 반드시 넣어야 하고, 에이전트가 한 일의 책임은 그 에이전트를 실행한 사용자에게 있습니다.

## 디버깅

디버깅을 위해 **GPU를 점유**해야 하는 경우가 있습니다.

--8<-- "gpu-session-rules.md"

!!! note "인터랙티브 잡은 requeue되지 않습니다"
    `srun --pty`, `salloc` 잡은 선점되면 되살아나지 않고 그대로 사라집니다. 잃으면 곤란한 작업은 배치 잡으로 돌리세요.

!!! danger "위반 시"
    규칙을 지키지 않은 GPU 점유 잡은 **관리자 판단으로 강제 종료**될 수 있고, 누적되면 **제재 대상**이 됩니다.
    **연달아 오래 점유해 자원 순환을 막는다고 판단되는 경우**에도 같은 조치가 적용됩니다.

### 실행 중인 잡의 노드에 들어가야 할 때

작업 현황 확인이나 디버깅을 위해 잡이 도는 노드에 들어가야 한다면, 아래 명령으로 그 잡 안에 터미널을 받으세요.

```bash
srun --jobid=<JOBID> --overlap --pty bash -i
```

이 밖에 **시스템 감시를 우회**해 자원을 점유하거나, **할당받지 않은 자원을 비정상적으로 사용**하는 행위는 **무관용 원칙**으로 엄중히 조치합니다.

## 접속 보안

보안을 위해 **모든 노드의 방화벽이 켜져 있고**, 외부에서 접속하는 로그인 노드에는 **무차별 대입 방어**가 상시 동작합니다.

- 일정 기간 안에 **비밀번호를 여러 번 틀리면 접속 IP가 차단**됩니다. 차단 기준은 공개하지 않습니다.
- 차단되었다면 <!-- BEGIN GENERATED: bot:unban -->`/cluster unban`으로 해제를 신청해 주세요.<!-- END GENERATED: bot:unban --> -> [도움 받기](../help.md)
- **반드시 SSH 키를 등록**해 비밀번호 없이 접속하세요. -> [SSH 키 등록 방법](../start/connect.md)
- 접속 주소와 포트는 계정을 발급할 때 관리자가 알려 줍니다 (`<로그인 주소>`, `<SSH 포트>`).

## 로그인 노드

로그인 노드는 모두가 함께 쓰는 접속 지점입니다. 안정성을 위해 **사용자별 자원 한도**가 걸려 있습니다. <!-- BEGIN GENERATED: login:limits -->로그인 노드에는 한 사람당 CPU 8개, 메모리 64 GB, 프로세스 4,096개까지 쓰실 수 있도록 제한이 걸려 있습니다.<!-- END GENERATED: login:limits -->

- VSCode 접속, 코드 편집, 가벼운 작업에는 지장이 없는 수준입니다.
- **무거운 연산은 반드시 Slurm으로 계산 노드에 제출**하세요. -> [첫 잡 실행하기](../start/first-job.md)
- 원격 편집은 **VSCode Remote-SSH**를 쓰세요. VSCode Tunnel은 로그인 노드의 CPU를 많이 차지합니다.

## AI 사용 규정

AI 코딩 에이전트(Claude Code, Codex CLI 등)는 쓸 수 있지만, **[AI 에이전트 규칙](ai-agents.md)을 반드시 따라야 합니다.**
에이전트는 사람보다 훨씬 빠르게, 지치지 않고 명령을 반복합니다. 실제로 AI 도구가 SSH 접속을 끝없이
재시도하다가 **기관 네트워크에서 클러스터 전체의 IP가 차단된** 사고가 있었고, 무분별한 잡 제출은
**GPU 자원 파편화**를 일으킵니다.

그래서 사용하는 모든 에이전트에 이 규칙을 **반드시 넣어야** 합니다. 넣는 방법은 [AI 에이전트 규칙](ai-agents.md) 첫머리에 있습니다.
에이전트가 규칙을 어겨도 **책임은 그 에이전트를 실행한 사용자**에게 있습니다.

## 위반 시 조치

| 행위 | 결과 |
|---|---|
| 규칙을 지키지 않은 GPU 점유 잡 | 관리자 판단으로 강제 종료, 누적 시 제재 |
| 오래 연달아 점유해 자원 순환 방해 | 위와 같음 |
| 시스템 감시 우회, 비정상 자원 점유 | 무관용 원칙, 엄중 조치 |
| 비밀번호 반복 오류 | 접속 IP 차단 |
| AI 에이전트 규칙 위반 (재시도 루프, 무분별한 제출 등) | 해당 잡 종료, 클러스터 이용 제한 가능 |

## 제출 전 체크리스트

- [ ] GPU 타입을 명시했나요? (`--gres=gpu:<GPU 타입>:N`)
- [ ] 노드당 GPU 수가 1, 2, 4, 8 중 하나인가요?
- [ ] GPU를 점유하는 세션이라면 팀 QoS인가요? (`qos` 로 본인 QoS 확인)
- [ ] 기본 QoS로 도는 긴 잡이라면 선점에 대비해 체크포인트를 남기나요?
- [ ] GPU 잡이라면 파티션, CPU, 메모리를 직접 지정하지 않았나요? (메모리를 적으면 제출이 거부됩니다)
- [ ] AI 에이전트가 제출한다면 그 에이전트에 [AI 에이전트 규칙](ai-agents.md)을 넣었나요?

실제 명령 예시는 [잡 레시피](../guide/job-recipes.md)를 보세요.
