# AI 에이전트 규칙

이 규칙은 **다른 사람과 함께 쓰는 자원(네트워크, 스케줄러, GPU, 공유 스토리지)에 영향을 주는 행동**에만 적용된다.
그 밖에 AI 도구를 쓰는 방식(어떤 도구와 모드를 쓸지, 내 파일과 내 잡을 어떻게 다룰지)은 사용자가 정한다.
자동 승인 모드에서도 이 규칙은 그대로 적용된다.

## 접속과 전송

- 원격 접속(SSH, `scp`, `rsync`)이 실패하면 같은 서버에 **30초 이상** 간격으로 **최대 2번** 다시 시도한다.
  첫 시도를 포함해 세 번 연달아 실패하면 그 서버에는 더 접속하지 않고 **사용자에게 보고**한다.
    - 실패 횟수는 **서버마다 따로** 센다. 한 서버의 횟수는 **그 서버에** 접속이 성공했을 때만 처음부터 다시 센다.
      다른 서버에 접속이 성공해도 그 횟수는 그대로다. 접속이 잘 되는 동안의 접속 횟수를 제한하는 규칙이 아니다.
    - 예: 서버 A에 두 번 실패하고 세 번째에 성공하면 A의 횟수는 처음부터 다시 센다. 그사이 서버 B에 세 번 연달아
      실패했다면, A 접속이 잘 되더라도 B에는 더 시도하지 않고 보고한다.
    - 인증 실패(`Permission denied`, 틀린 비밀번호나 키)는 다시 시도하지 않고 바로 보고한다. 인증 실패가 쌓이면
      접속한 IP가 차단된다.
    - 자동 재시도 루프를 만들지 않는다.
- 접속이 잘 되더라도 짧은 시간에 새 접속을 여러 번 열지 않는다. 여러 명령은 한 번의 접속에서 실행하고
  (`ssh 서버 'cmd1 && cmd2'`), 같은 서버에 자주 접속하면 연결을 다시 쓴다([접속하기](../start/connect.md)의
  `~/.ssh/config` 예시처럼 `ControlMaster`를 켠다).
- 전송(`scp`, `rsync` 등)은 서버가 달라도 동시에 여러 개 띄우지 않는다. 앞의 전송이 끝난 뒤 다음 전송을 시작한다.

이유: 끝없는 접속 재시도로 기관 네트워크에서 클러스터 전체의 IP가 차단된 사고가 실제로 있었다.

## 잡 제출

- 잡을 내기 전에 **`sq`로 현재 자원 현황을 확인**한다. 잡 여러 개나 배열 잡을 한꺼번에 낼 때는 그 전에 한 번만 확인한다.
- GPU는 **필요한 만큼만** 요청하고, 그 수는 아래 [잡 제출 규칙](rules.md#잡-제출-규칙)의 노드당 GPU 수에 맞춘다.
  예: GPU 1장으로 실행되는 실험이면 1장만 요청한다.
- 비슷한 잡이 여러 개면 하나씩 반복 제출하지 않고 **배열 잡과 동시 실행 상한**을 쓴다(`--array=0-99%4`).
- GPU를 점유하는 세션(정의는 아래 "GPU를 점유하는 세션의 규칙")을 열어 둔 채 사용자의 다음 지시를 기다리지 않는다.
  사용자에게 묻기 전에 그 세션을 반납한다.

## 요청을 몰아서 보내지 않기

- 짧은 시간에 많은 요청을 보내지 않는다. SSH 접속이나 `squeue`, `sq`, `sacct` 같은 스케줄러 조회를 빠르게 반복하면(예: `watch -n 1`)
  스케줄러와 네트워크가 느려져 모든 사람이 영향을 받는다.
- 잡이 끝나기를 기다릴 때는 반복 조회 대신 **`sbatch --wait`**, `srun`(끝날 때까지 기다림), 또는 `--dependency`를 쓴다.
- 상태를 계속 지켜봐야 하면 직접 반복하지 않고 `sq -i <초>`를 쓴다. `sq`는 너무 짧은 간격을 받지 않고, Slurm이 답하지 않으면
  스스로 간격을 늘린다.
- 클러스터 명령 가운데 `--json`이 있는 명령(<!-- BEGIN GENERATED: commands:json -->`qos`, `sq`, `usage`<!-- END GENERATED: commands:json -->, 하위 명령 포함)의 결과는
  화면 출력을 해석하지 않고 `--json`으로 읽는다. Slurm이나 Prometheus가 답하지 않아 실패한 명령은 반복해서 다시 실행하지 않는다.
  출력 형식과 종료 코드는 각 명령의 `-h`(예: `usage -h`)에 있다.

## 장시간 세션

에이전트를 오래 실행할 때는 아래를 반드시 지킨다.

- 직접 띄운 백그라운드 프로세스, 끝나지 않은 하위 프로세스, 좀비 프로세스를 남기지 않는다. 다 쓴 것은 정리한다.
- 메모리, 열린 파일, 임시 파일이 계속 늘어나는 누수가 없는지 살핀다.
- 세션을 끝낼 때 그 세션이 띄운 프로세스를 정리하고, 그 세션이 낸 잡 가운데 더 실행할 필요가 없는 잡(열어 둔 `salloc` 할당 등)을
  취소한다. 사용자가 실행하라고 한 잡은 그대로 둔다.
