# 클러스터 사용 규정

!!! warning "모든 사용자가 반드시 숙지해야 합니다"
    규정을 몰라서 생긴 불이익은 구제해 드리기 어렵습니다.
    한 사람의 부주의가 다른 동료들의 연구 일정에 큰 지장을 줄 수 있습니다. 함께 쓰는 환경이니 서로 배려해 주세요.

모든 사용자가 지켜야 하는 클러스터 사용 규정입니다. 지금 유효한 규정은 이 페이지에 있습니다. 공지에서는 무엇이 언제부터 바뀌는지 알려 드립니다.

## 핵심 요약

1. **GPU를 점유하는 세션**(인터랙티브 셸, 노트북, 대기 중인 추론 서버 등)은 **팀 QoS**로 실행하고, 다 쓰면 **즉시 반납**하세요.
2. **SSH 키를 반드시 등록**하세요. 비밀번호를 여러 번 틀리면 접속 IP가 차단됩니다.
3. **AI 에이전트(Claude Code, Codex CLI 등)는 쓸 수 있지만, 그 에이전트에 [AI 에이전트 규칙](ai-agents.md)을 반드시 넣어야 합니다.** 에이전트가 한 일의 책임은 그 에이전트를 실행한 사용자에게 있습니다.

## 잡 제출 규칙

모든 잡은 반드시 아래 규칙을 따라야 합니다.

--8<-- "job-rules.md"

규칙마다의 이유:

- **CPU와 메모리**: CPU나 메모리를 GPU 수에 비례한 양보다 많이 잡으면 그 노드에 남은 GPU를 다른 사람이 쓰지 못합니다. 그래서 제출할 때 시스템이 이 규칙을 강제로 적용합니다.
- **노드당 GPU 수**: 8은 1, 2, 4로 나누어떨어지므로 같은 크기의 잡끼리 GPU 8장 노드를 남김없이 채울 수 있습니다.
  3장은 그렇지 않습니다. 예를 들어 8장 노드에서 3장 잡이 실행되면 5장이 남습니다. 이 5장에는 8장 잡이 들어가지 못하고,
  4장 잡을 넣으면 남은 1장은 1장 잡만 쓸 수 있습니다.
- **CPU 전용 잡의 `--exclusive`, `--mem=0`**: 그 잡이 실행되는 내내 그 노드의 GPU를 아무도 쓰지 못하기 때문입니다.

!!! tip "QoS가 무엇인지, 내 팀 QoS가 무엇인지 모르겠다면"
    `qos` 를 실행하세요. 쓸 수 있는 QoS, 선점 관계(무엇을 선점하고 무엇에 선점당하는지), 팀 몫 사용량이 한 번에 나옵니다.
    배경 설명은 [Slurm 레퍼런스: QoS](../reference/slurm.md#qos)를 보세요.

## 디버깅

디버깅을 위해 **GPU를 점유**해야 하는 경우가 있습니다.

--8<-- "gpu-session-rules.md"

**GPU를 점유하는 세션의 규칙**

| # | 규칙 | 예시 |
|---|---|---|
| 1 | **본인 소속 팀 QoS**로 실행 | `--qos=<팀 QoS>` (`qos`로 확인) |
| 2 | 다 쓰면 **즉시 반납** | 셸에서 `exit`, 또는 `scancel <JOBID>` |

!!! note "인터랙티브 잡은 requeue되지 않습니다"
    `srun --pty`, `salloc` 잡은 선점되면 되살아나지 않고 그대로 사라집니다. 잃으면 곤란한 작업은 배치 잡으로 돌리세요.

!!! danger "위반 시"
    규칙을 지키지 않은 GPU 점유 잡은 **관리자 판단으로 강제 종료**될 수 있고, 누적되면 **제재 대상**이 됩니다.
    GPU를 **연달아 오래 점유해 다른 사람이 차례를 얻지 못한다고 관리자가 판단하면** 같은 조치를 합니다.

### 실행 중인 잡의 노드에 들어가야 할 때

작업 현황 확인이나 디버깅을 위해 잡이 실행 중인 노드에 들어가야 한다면, 아래 명령으로 그 잡 안에서 셸을 받으세요.

```bash
srun --jobid=<JOBID> --overlap --pty bash -i
```

이 밖에 **시스템 감시를 우회**해 자원을 점유하거나 **할당받지 않은 자원을 비정상적으로 쓰면**, 예외 없이(**무관용 원칙**) 엄중히 조치합니다.

## 접속 보안

보안을 위해 **모든 노드의 방화벽이 켜져 있고**, 외부에서 접속하는 로그인 노드에는 **무차별 대입 방어**가 상시 동작합니다.

- 일정 기간 안에 **비밀번호를 여러 번 틀리면 접속 IP가 차단**됩니다. 차단 기준은 공개하지 않습니다.
- 차단되었다면 <!-- BEGIN GENERATED: bot:unban -->`/cluster unban`으로 해제를 신청해 주세요.<!-- END GENERATED: bot:unban --> -> [도움 받기](../help.md)
- **반드시 SSH 키를 등록**해 비밀번호 없이 접속하세요. -> [SSH 키 등록 방법](../start/connect.md)
- 접속 주소와 포트는 계정을 발급할 때 관리자가 알려 줍니다 (`<로그인 주소>`, `<SSH 포트>`).

### SSH 접속 빈도

<!-- BEGIN GENERATED: rule:ssh-rate -->
로그인 노드에 새 SSH 접속을 **10분 동안 100번** 열면, 그 뒤의 새 접속이 **10분** 동안 막힙니다. 막힌 동안에도 접속을 계속 시도하면 막히는 시간이 늘어나 처음 막힌 때부터 최대 **60분**까지 갑니다. 10분 동안 90번에 이르면 미리, 막히면 바로 DM으로 알려 드립니다.
<!-- END GENERATED: rule:ssh-rate -->

- 로그인 노드에 새로 여는 SSH 접속만 셉니다. 이미 연 접속을 다시 쓰는 창(`ControlMaster`)과 열려 있는 세션은 세지 않고, 관리자 계정과 시스템 계정도 세지 않습니다.
- 접속을 줄이는 방법과 막혔을 때 할 일은 [접속하기: 새 접속 줄이기](../start/connect.md#5-새-접속-줄이기)에 있습니다.

## 로그인 노드

로그인 노드는 모두가 함께 쓰는 접속 지점입니다. 안정성을 위해 **사용자별 자원 한도**가 걸려 있습니다. <!-- BEGIN GENERATED: login:limits -->로그인 노드에서는 한 사람이 CPU 8개, 메모리 64 GB, 프로세스 4,096개까지 쓰실 수 있습니다.<!-- END GENERATED: login:limits -->

- VSCode 접속, 코드 편집, 가벼운 작업에는 지장이 없는 수준입니다.
- **무거운 연산은 반드시 Slurm으로 계산 노드에 제출**하세요. -> [첫 잡 실행하기](../start/first-job.md)
- 원격 편집은 **VSCode Remote-SSH**를 쓰세요. VSCode Tunnel은 로그인 노드의 CPU를 많이 차지합니다.

## AI 사용 규정

AI 코딩 에이전트(Claude Code, Codex CLI 등)는 쓸 수 있습니다. 다만 에이전트는 사람보다 훨씬 빠르게, 지치지 않고 명령을 반복합니다.
실제로 AI 도구가 SSH 접속을 끝없이 재시도하다가 **기관 네트워크에서 클러스터 전체의 IP가 차단된** 사고가 있었습니다.
또 에이전트가 잡을 마구 내면 빈 GPU가 여러 노드에 조금씩 흩어져, 큰 잡이 들어갈 노드가 없어집니다(**GPU 자원 파편화**).

그래서 사용하는 모든 에이전트에 **[AI 에이전트 규칙](ai-agents.md)을 반드시 넣어야** 합니다. 넣는 방법은 그 페이지 첫머리에 있습니다.
에이전트가 규칙을 어겨도 **책임은 그 에이전트를 실행한 사용자**에게 있습니다.

## 위반 시 조치

| 행위 | 결과 |
|---|---|
| 규칙을 지키지 않은 GPU 점유 잡 | 관리자 판단으로 강제 종료, 누적 시 제재 |
| GPU를 연달아 오래 점유해 다른 사람의 차례를 막음 | 위와 같음 |
| 시스템 감시 우회, 비정상 자원 점유 | 무관용 원칙, 엄중 조치 |
| 비밀번호 반복 오류 | 접속 IP 차단 |
| AI 에이전트 규칙 위반 (재시도 루프, 무분별한 제출 등) | 해당 잡 종료, 클러스터 이용 제한 가능 |
