# AI 에이전트 규칙

이 페이지는 사람이 읽는 규정이면서, **AI 코딩 에이전트(Claude Code, Codex CLI 등)에게 그대로 주는 지침**입니다.
클러스터는 이 내용을 지원하는 에이전트에 자동으로 넣어 둡니다. 다른 에이전트를 쓴다면 세션을 시작할 때
이 페이지를 읽히세요. 에이전트가 한 일의 책임은 그 에이전트를 실행한 사용자에게 있습니다.

규칙의 기준은 하나입니다. **다른 사람이 함께 쓰는 자원(네트워크, 스케줄러, GPU, 공유 스토리지)에 영향을 주는 행동**만
규칙으로 정하고, 내 파일과 내 잡을 어떻게 다룰지는 사용자의 판단에 맡깁니다.

## 접속과 전송

- SSH, `scp`, `rsync` 등 원격 접속 시도는 **연속 최대 2회**, 시도 사이에 **1분 이상** 간격을 둔다.
  두 번 다 실패하면 **멈추고 사용자에게 보고**한다. 자동 재시도 루프를 만들지 않는다.
- 데이터 전송은 **사용자가 확인한 뒤** 실행하고, 여러 전송을 동시에 띄우지 않는다.

이유: 끝없는 접속 재시도 때문에 기관 네트워크에서 클러스터 전체의 IP가 차단된 사고가 실제로 있었습니다.

## 잡 제출

- 제출하기 전에 **`sq`로 현재 자원 현황을 확인**하고, 남은 GPU를 잘게 쪼개 다른 사람의 큰 잡이
  들어가지 못하게 만들지 않는 크기를 고른다.
- [잡 제출 규칙](index.md#잡-제출-규칙)을 그대로 지킨다: **GPU 타입 명시** (`--gres=gpu:<GPU 타입>:<개수>`),
  **파티션, CPU, 메모리 지정 금지**, **노드당 GPU 수는 1, 2, 4, 8**.
- 비슷한 잡이 여러 개면 하나씩 반복 제출하지 말고 **배열 잡과 동시 실행 상한**을 쓴다 (`--array=0-99%4`).
- GPU를 점유하는 작업은 사람과 똑같이 [디버깅 규칙](index.md#디버깅)을 따르고, 끝나면 즉시 반납한다.
  GPU를 잡아 둔 채로 사용자의 다음 지시를 기다리지 않는다.

## 기다리기와 상태 조회

- 잡이 끝나기를 기다릴 때는 반복 조회 대신 **`sbatch --wait`**, `srun`(끝날 때까지 기다림), 또는
  `--dependency`를 쓴다.
- 반복 조회가 꼭 필요하면 `squeue`, `sq`, `sacct`를 **30초 이상** 간격으로 부른다. `watch -n 1` 같은 짧은
  반복은 스케줄러를 느리게 해 모든 사람에게 영향을 준다.

사람이 필요할 때 `sq`를 치는 것은 제한이 없습니다. 이 규칙은 자동으로 도는 반복에만 적용됩니다.

## 로그인 노드와 공유 스토리지

- 로그인 노드에서 학습, 대용량 전처리 같은 무거운 연산을 돌리지 않는다. 연산은 Slurm 잡으로 낸다.
- `/home` 전체나 공유 스토리지 전체를 훑는 검색(`find /`, `find /home`, 전체 `grep -r`)을 하지 않는다.
  검색은 내 디렉터리나 프로젝트 안에서 한다.

이유: 공유 스토리지 전체를 훑으면 파일 서버가 포화되어 모든 사용자의 작업이 느려집니다.

## 비밀 정보

- 비밀번호, 토큰, 개인 키를 대화에 넣거나 출력하지 않는다. `~/.ssh`, 인증 파일을 읽거나 옮기지 않는다.

## 사용자에게 권하는 것 (규정은 아님)

- 대량 삭제나 여러 잡 취소 전에는 에이전트가 한 번 확인받게 하면 실수를 줄일 수 있습니다.
- 에이전트가 만든 잡 스크립트는 제출 전에 한 번 읽어 보세요.
